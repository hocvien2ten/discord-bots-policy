1. Operator and scope

These three applications are operated by the owner of the Học Viện 2Ten Discord server, reachable on Discord as baobabi.1. They operate within that configured server and are not operated by Discord or an AI provider.

This policy covers only the three Discord applications identified above and their server features. Application names and avatars may change; the application IDs identify the services covered.

2. Information used by each bot

Ram: games and community features

Ram processes Discord user, guild, channel, message and role identifiers, profile information, membership and role changes, and gameplay records. Gameplay records include inventories, character ownership, virtual balances, progression, couples, rewards, marketplace activity, cooldowns and transaction receipts. They maintain ongoing accounts and help prevent duplicate rewards or payments.

Ram reads prefix commands, game entries and participating players’ follow-up answers. Its word-chain games retain accepted entries and the last player identifier until the game resets.

For liked-post rankings, Ram stores a post excerpt of up to 1,000 JavaScript string units, together with its message and channel identifiers, author relationship and Like count. This feature operates in channels visible to the bot within the configured server. Stored excerpts are not automatically synchronized with later edits to the original post.

Emilia: moderation

Emilia processes member and role information for moderator-authorized jail cases, role removal and restoration, reapplying active restrictions when a member rejoins, and recovery after interrupted operations. Cases can include participant identifiers, usernames or display names, avatar URLs, reasons, guild and channel identifiers, affected roles, timestamps and related reward or penalty status.

Its media-deletion workflow examines image or video attachment metadata and recent audit-log events. Thread starter content and attachment metadata can also be cached in process memory for the thread-handling workflow. Emilia does not provide a general-purpose archive of all server conversations.

Beatrice: economy and quizzes

Beatrice processes user and channel identifiers and economy records for Gold, inventory, chat-activity rewards, bets and quizzes. Its chat-Gold handler does not store ordinary chat text. Quiz state includes the question, normalized answer, creator and participant identifiers, message and channel identifiers, timestamps and winner or reward status. Betting state includes questions, options, participants, stakes and settlement status.

Beatrice does not perform mass messaging. Its optional daily Booster-reward feature is currently disabled.

3. AI processing and service providers

Ram uses external AI inference services for selected game dialogue, question generation and Treasure answer grading. Treasure grading sends the generated question, expected answers and the participating player’s sanitized answer. The answer is limited to 140 Unicode code points; URLs are removed and Discord mention tokens are replaced. Requests may pass through an operator-managed gateway before reaching an external provider.

The bot application code does not train or fine-tune models using Discord messages. Emilia and Beatrice have no AI-processing workflow. External providers may process or retain submitted data under their own terms. The statement about the bot code does not establish a uniform no-training or immediate-deletion guarantee across downstream providers; such a guarantee has not been independently verified.

Infrastructure, image-delivery and inference providers process the data needed to operate the corresponding features. Bot tokens and other access credentials are kept outside public source code and are not included in application-review evidence.

4. Storage, security and retention

The primary bot-data and persistent service-log directories are stored on an encrypted volume. Access is limited to authorized operators and the runtime services that need it. This description concerns those storage directories and is not a claim that all temporary operational copies or external-provider systems use the same storage arrangement.

There is no blanket automatic deletion of every record after 30 days:

  • Gameplay and economy: records persist to maintain accounts and reconcile transactions.
  • Liked posts: Ram has no automatic age-based expiry. Records can be removed when the bot observes the last Like being removed, the post being deleted, or its channel or thread being deleted.
  • Word-chain entries: entries are cleared when a game resets rather than after a fixed number of days.
  • Moderation: Emilia retains open cases and up to 2,000 closed cases by count. Its thread cache is held in memory, is cleared by process restart and has no fixed time-based expiry.
  • Quizzes and bets: completed Beatrice quizzes are removed after reward confirmation and successful announcement. Unresolved quizzes and recovery records persist. Bets remain until settlement or cancellation.
  • Backups: copies can contain earlier records; there is no blanket automatic 30-day deletion schedule.

Data requests are handled manually as described below. Records that are no longer necessary, or whose deletion is required, must be addressed through that process. Transaction receipts require care so that deleting identifying data does not cause a completed reward or payment to be applied again.

5. Choices and processing boundaries

There is currently no general per-user command to opt out of every processing workflow. You can choose not to enter a game or submit a quiz answer, but that is not a complete opt-out from moderation, configured chat rewards or liked-post processing.

Server administrators control the channels and roles the applications can access and the applicable moderation exemptions. For an individual data request, contact the operator below rather than assuming that not invoking a command removes existing data.

6. Access, correction and deletion requests

Private contact: contact baobabi.1 on Discord.

If you cannot reach that account: open a privacy-contact request in this policy’s GitHub issue tracker to ask for a private contact route.

GitHub issues are public. Do not put your Discord user ID, messages, moderation details or other personal information in a public issue.

Through the private contact route, identify the bot, the relevant account or data, and whether you want access, correction or deletion. Never send passwords, bot tokens, API keys or recovery codes.

Requests are reviewed and handled manually. The operator may ask for reasonable proof of account ownership, identify the relevant records and backup copies, and explain the action taken and any necessary retention. Records needed to reconcile completed transactions must be handled without duplicating rewards or payments. There is no self-service deletion command or guaranteed automatic 30-day expiry.

7. This policy page and updates

This static page does not add analytics, tracking scripts, advertising or contact forms. GitHub Pages hosts it and processes visitor network information, including IP addresses, for security under the GitHub Privacy Statement. An issue posted to the linked tracker is public.

We will update this page when these applications or their data practices change. The date above identifies this version; its publication history is available in the policy repository.
